# `vpx/src/vpx_codec.c` — the codec-agnostic public API

## Role in the decoder

Every libvpx codec ships behind a single, uniform C API. An application
that wants to decode VP8 includes `vpx/vpx_decoder.h`, asks for the
interface pointer with `vpx_codec_vp8_dx()`, and calls
`vpx_codec_dec_init`, `vpx_codec_decode`, `vpx_codec_get_frame`, and
`vpx_codec_destroy`. None of those entry points know anything about VP8
specifically — they treat the codec as an opaque object behind a
function-pointer table (`vpx_codec_iface_t`).

`vpx_codec.c` is the **bottom half of that dispatcher**. It implements
the part of the public API that has nothing to do with whether the
codec is an encoder or a decoder, VP8 or VP9: version queries, error
string translation, `vpx_codec_destroy`, `vpx_codec_get_caps`, and the
type-unsafe trampoline `vpx_codec_control_`. Two sibling files —
`vpx_decoder.c` and `vpx_encoder.c` — handle the decode- and
encode-specific surface (init, decode, get_frame, encode, etc.).
Together those three files plus `vpx_image.c` are the entire `vpx/src/`
layer; in the minimal VP8 decoder build they are the only files
outside of `vp8/`, `vpx_dsp/`, and `vpx_mem/` that an application
links against from the public-API side.

The dispatcher sits **above** the codec-specific adapter
`vp8/vp8_dx_iface.c`. That file defines a `vpx_codec_iface_t` named
`vpx_codec_vp8_dx_algo` and fills its function-pointer slots with VP8
implementations (`vp8_init`, `vp8_destroy`, `vp8_decode`, …). When the
application calls `vpx_codec_destroy(&ctx)`, the call lands here, this
file validates the context, and then dispatches through
`ctx->iface->destroy(ctx->priv)` into VP8 code. The dispatcher never
imports a VP8 header; the indirection is entirely through the
generic `vpx_codec_iface_t` interface struct defined in
`vpx/internal/vpx_codec_internal.h`.

The file is short — barely 130 lines — but it pins down several
load-bearing conventions used by every codec in the tree:

  - error codes are an enum (`vpx_codec_err_t`) translated to printable
    strings by a single switch;
  - the per-instance error state lives in `ctx->err` and is updated by
    every public API call via the `SAVE_STATUS` macro;
  - control IDs are dispatched through a per-codec table
    (`vpx_codec_ctrl_fn_map_t[]`) walked linearly;
  - long-jump-based error reporting (`vpx_internal_error`) is the
    common bail-out path used by deep-stack decoder code.

The narrative below walks every definition in declaration order.

## Headers and the SAVE_STATUS macro

```c
#include <stdarg.h>
#include <stdio.h>
#include <stdlib.h>
#include "vpx/vpx_integer.h"
#include "vpx/internal/vpx_codec_internal.h"
#include "vpx_version.h"

#define SAVE_STATUS(ctx, var) (ctx ? (ctx->err = var) : var)
```

The only non-system header used for type definitions is
`vpx/internal/vpx_codec_internal.h`. That header declares the private
guts of the interface — `struct vpx_codec_iface`, `vpx_codec_priv`,
the function-pointer typedefs (`vpx_codec_init_fn_t`,
`vpx_codec_destroy_fn_t`, …), the control-mapping table type
`vpx_codec_ctrl_fn_map_t`, and the `vpx_internal_error_info` struct
used for `setjmp`/`longjmp`-style error reporting. By including the
internal header (which itself includes the public `vpx_decoder.h` and
`vpx_encoder.h`), this file gets both the application-facing and
implementation-facing views of the API in a single translation unit.

`vpx_version.h` is generated by `./configure` and defines the three
version macros consumed below: `VERSION_PACKED`,
`VERSION_STRING_NOSP`, `VERSION_EXTRA`.

`SAVE_STATUS` is the file's lone macro and it is used by every public
entry point that takes a `vpx_codec_ctx_t *`. Its job is to stash the
return value into `ctx->err` *while also returning it*, so that the
two channels through which the caller can discover the error
(function return value and `vpx_codec_error(&ctx)`) always agree.
It is written as a ternary because the context pointer may itself be
NULL — in that case there is no `ctx->err` to update and only the
function-return-value channel is available.

The reason this lives as a macro rather than a helper is that it needs
the address of `ctx->err` and must be cheap and inlined everywhere; it
appears on the return path of `vpx_codec_destroy` and
`vpx_codec_control_` here, and again on the corresponding paths in
`vpx_decoder.c` and `vpx_encoder.c`.

## Version queries

### `vpx_codec_version`, `vpx_codec_version_str`, `vpx_codec_version_extra_str`

```c
int vpx_codec_version(void) { return VERSION_PACKED; }
const char *vpx_codec_version_str(void) { return VERSION_STRING_NOSP; }
const char *vpx_codec_version_extra_str(void) { return VERSION_EXTRA; }
```

Three trivial accessors over compile-time-defined macros from
`vpx_version.h`. Their purpose is to give applications a runtime
handle on the library version without forcing them to recompile when
libvpx is upgraded. `vpx_codec_version` returns a packed
`major<<16 | minor<<8 | patch` integer; the public header in
`vpx/vpx_codec.h` ships the matching `VPX_VERSION_MAJOR/MINOR/PATCH`
extraction macros so callers can compare numerically.

The reason for *three* separate functions (rather than one struct
returning all of it) is ABI stability: each is a separate symbol, so
adding a fourth — say, `vpx_codec_build_config()`, which exists but is
implemented elsewhere — doesn't perturb the layout of an aggregate.
The version-text variants are used by examples and by the `vpxdec`
command-line tool for `--version` output.

There is no failure mode: the macros are always defined by the
generated header, and the strings have static-storage lifetime.

## Names, capabilities, and string translation

### `vpx_codec_iface_name`

```c
const char *vpx_codec_iface_name(vpx_codec_iface_t *iface) {
  return iface ? iface->name : "<invalid interface>";
}
```

The interface struct `vpx_codec_iface` (defined in
`vpx/internal/vpx_codec_internal.h`) begins with a `const char *name`
field. For VP8 the adapter file `vp8/vp8_dx_iface.c` initializes it to
`"WebM Project VP8 Decoder"` (and the encoder side fills in
`"WebM Project VP8 Encoder"`). Applications that want a printable
description — for `--help` output, for example — go through this
accessor rather than reaching into the struct, since the struct is
declared `typedef const struct vpx_codec_iface vpx_codec_iface_t;` and
its layout is technically opaque to applications.

The NULL guard returning a literal placeholder is defensive: passing
a NULL iface is a programming error, but printing
`"<invalid interface>"` is friendlier than crashing inside a
diagnostic.

### `vpx_codec_err_to_string`

```c
const char *vpx_codec_err_to_string(vpx_codec_err_t err) {
  switch (err) {
    case VPX_CODEC_OK: return "Success";
    case VPX_CODEC_ERROR: return "Unspecified internal error";
    case VPX_CODEC_MEM_ERROR: return "Memory allocation error";
    ...
    case VPX_CODEC_LIST_END: return "End of iterated list";
  }
  return "Unrecognized error code";
}
```

This is the canonical translation between the `vpx_codec_err_t`
enum (declared in `vpx/vpx_codec.h`) and human-readable strings.
The switch enumerates every enumerator the public header defines, in
declaration order:

  - `VPX_CODEC_OK` — operation succeeded;
  - `VPX_CODEC_ERROR` — generic internal failure with no better label;
  - `VPX_CODEC_MEM_ERROR` — `vpx_malloc` (or an internal allocator)
    returned NULL;
  - `VPX_CODEC_ABI_MISMATCH` — the caller's `VPX_*_ABI_VERSION` does
    not match what the library was compiled with (raised by
    `vpx_codec_dec_init_ver` in `vpx_decoder.c`);
  - `VPX_CODEC_INCAPABLE` — the codec interface lacks the requested
    capability (e.g. asking a decoder to encode);
  - `VPX_CODEC_UNSUP_BITSTREAM` — the input does not parse as the
    declared codec at all; fatal to the stream;
  - `VPX_CODEC_UNSUP_FEATURE` — the input is recognized but uses a
    profile/feature not supported in this build; may be fatal to a
    GOP;
  - `VPX_CODEC_CORRUPT_FRAME` — bitstream-level corruption in a
    specific frame;
  - `VPX_CODEC_INVALID_PARAM` — caller passed a bad argument (NULL ctx,
    out-of-range value, etc.);
  - `VPX_CODEC_LIST_END` — sentinel returned by iterator-style APIs
    when the list is exhausted.

The trailing `return "Unrecognized error code"` is reachable only if
an integer value outside the enum is cast in — useful for catching
ABI drift in a stale caller. Because every case `return`s, no `break`s
are needed and there is no fall-through risk.

The invariant maintained here is that **the array of strings must
stay in lock-step with the enum**. If `vpx_codec_err_t` ever gains a
new value, this switch must gain a new case; the compiler's
`-Wswitch-enum` (with no `default:`) is the safety net.

### `vpx_codec_error`

```c
const char *vpx_codec_error(const vpx_codec_ctx_t *ctx) {
  return (ctx) ? vpx_codec_err_to_string(ctx->err)
               : vpx_codec_err_to_string(VPX_CODEC_INVALID_PARAM);
}
```

A trivial wrapper around `vpx_codec_err_to_string` that consults the
per-instance error code instead of taking it as an argument. The whole
point of `ctx->err` being kept up to date by `SAVE_STATUS` is so this
accessor can be called at any time after a failure and return a
sensible string. The NULL-ctx branch transmutes "you called me wrong"
into the `INVALID_PARAM` string rather than crashing.

### `vpx_codec_error_detail`

```c
const char *vpx_codec_error_detail(const vpx_codec_ctx_t *ctx) {
  if (ctx && ctx->err)
    return ctx->priv ? ctx->priv->err_detail : ctx->err_detail;
  return NULL;
}
```

Two-tier error storage. The public `vpx_codec_ctx_t` carries a
`const char *err_detail`. The private `vpx_codec_priv_t` (allocated
by the codec-specific `init` function) carries its own
`const char *err_detail`. The convention is:

  - **Before** `init` succeeds, `ctx->priv` is still NULL, so any
    error string set during init (e.g. ABI mismatch) lives on
    `ctx->err_detail`.
  - **After** `init` succeeds, `ctx->priv` is non-NULL and the
    codec routes its detail strings through `ctx->priv->err_detail`.
    The VP8 path does this from `vp8_dx_iface.c` (see e.g. how it
    surfaces "Invalid frame width" etc.).

This function picks the appropriate slot at read time. The detail is
suppressed entirely when `ctx->err == VPX_CODEC_OK` — there is no
"successful detail" — and when either `ctx` is NULL (caller error) or
no detail was provided (transient failures often skip the
human-readable text). The doxygen contract in `vpx_codec.h` notes that
the returned string is invalidated by the next call other than
`vpx_codec_error*`, since the next call typically overwrites or frees
the private buffer.

## The destructor

### `vpx_codec_destroy`

```c
vpx_codec_err_t vpx_codec_destroy(vpx_codec_ctx_t *ctx) {
  vpx_codec_err_t res;

  if (!ctx)
    res = VPX_CODEC_INVALID_PARAM;
  else if (!ctx->iface || !ctx->priv)
    res = VPX_CODEC_ERROR;
  else {
    ctx->iface->destroy((vpx_codec_alg_priv_t *)ctx->priv);

    ctx->iface = NULL;
    ctx->name = NULL;
    ctx->priv = NULL;
    res = VPX_CODEC_OK;
  }

  return SAVE_STATUS(ctx, res);
}
```

The teardown counterpart to `vpx_codec_dec_init`/`vpx_codec_enc_init`.
Three branches:

  1. **NULL context** — bad call: `INVALID_PARAM`. There is no `ctx`
     to write to, so `SAVE_STATUS` simply returns the value without
     storing it.
  2. **Half-initialized context** — one of `iface` or `priv` is
     missing. This indicates a state that no public init function
     could leave the context in, so it's flagged as generic
     `VPX_CODEC_ERROR`. The destroy callback is *not* invoked, on the
     principle that a destructor handed an inconsistent input is
     better left untouched than running on garbage.
  3. **Fully initialized** — dispatch to the codec's own `destroy`
     hook (for VP8, this is `vp8_destroy` in `vp8_dx_iface.c`, which
     frees the decoder instance and any frame buffers), then zero out
     all of `iface`, `name`, and `priv`. The zeroing is what
     guarantees the context can be safely re-`destroy`d, or re-`init`d
     against a different codec, without the previous interface
     dangling.

The cast `(vpx_codec_alg_priv_t *)ctx->priv` deserves a note. The
public type is `vpx_codec_priv_t` — the small struct described in the
internal header. By the convention documented there, each codec
allocates a larger struct (`vpx_codec_alg_priv_t`, declared opaquely
in `vpx_codec_internal.h`) and ensures `vpx_codec_priv` is its first
member so the pointers are interchangeable. VP8 implements this by
making its own `vpx_codec_alg_priv_t` start with `vpx_codec_priv_t
base;`. The dispatcher does the upcast unconditionally because it
doesn't know — and shouldn't know — the algorithm-specific layout.

The post-condition is that on success, `ctx` is left in a
field-cleared state and `ctx->err == VPX_CODEC_OK`; on failure,
`ctx->err` records the reason and the underlying decoder (if any) is
left untouched.

## Capabilities query

### `vpx_codec_get_caps`

```c
vpx_codec_caps_t vpx_codec_get_caps(vpx_codec_iface_t *iface) {
  return iface ? iface->caps : 0;
}
```

A bitfield-style query against `iface->caps`. The bits that can appear
are defined in `vpx/vpx_codec.h`:

  - `VPX_CODEC_CAP_DECODER` (0x1) — the interface can decode;
  - `VPX_CODEC_CAP_ENCODER` (0x2) — the interface can encode;
  - `VPX_CODEC_CAP_HIGHBITDEPTH` (0x4) — supports >8 bits per sample.

The VP8 decoder adapter sets `VPX_CODEC_CAP_DECODER` only. The
returned value is used by applications (and by `vpx_decoder.c` /
`vpx_encoder.c`) to refuse to initialize an interface against the
wrong role: `vpx_codec_dec_init_ver` checks
`!(iface->caps & VPX_CODEC_CAP_DECODER)` and returns `INCAPABLE`.

The NULL-iface fall-back to 0 is the natural identity for a bitfield
and means `vpx_codec_get_caps(NULL) & ANYTHING == 0`; calling code
treats this the same as "no capabilities".

## The control trampoline

### `vpx_codec_control_`

```c
vpx_codec_err_t vpx_codec_control_(vpx_codec_ctx_t *ctx, int ctrl_id, ...) {
  vpx_codec_err_t res;

  if (!ctx || !ctrl_id)
    res = VPX_CODEC_INVALID_PARAM;
  else if (!ctx->iface || !ctx->priv || !ctx->iface->ctrl_maps)
    res = VPX_CODEC_ERROR;
  else {
    vpx_codec_ctrl_fn_map_t *entry;

    res = VPX_CODEC_INCAPABLE;

    for (entry = ctx->iface->ctrl_maps; entry->fn; entry++) {
      if (!entry->ctrl_id || entry->ctrl_id == ctrl_id) {
        va_list ap;

        va_start(ap, ctrl_id);
        res = entry->fn((vpx_codec_alg_priv_t *)ctx->priv, ap);
        va_end(ap);
        break;
      }
    }
  }

  return SAVE_STATUS(ctx, res);
}
```

The variadic underbar-suffixed function that all `vpx_codec_control(ctx,
id, data)` macros resolve to. It is the most subtle piece of code in
the file.

**Why a variadic dispatch instead of typed setters?** The public
header (`vpx/vpx_codec.h`) defines a family of helper macros
(`VPX_CTRL_USE_TYPE`, `VPX_CTRL_USE_TYPE_DEPRECATED`, `VPX_CTRL_VOID`)
that each codec uses to declare a per-control-ID inline wrapper with
a typed `data` parameter. Those wrappers, when expanded at the call
site by `vpx_codec_control(ctx, ID, value)`, call this function. The
control identifier space is open-ended (VP8 has its own IDs in
`vp8.h`/`vp8dx.h`; VP9 has more in `vp9dx.h`), so the dispatcher
itself must be type-agnostic; the `va_list` is the only portable way
to forward an arbitrarily typed payload.

**The three-stage filter:**

  1. `!ctx || !ctrl_id` — the caller passed nothing, or passed control
    ID 0. Zero is reserved as the end-of-list sentinel in the
    `ctrl_maps` array, so legitimate codec IDs are guaranteed to be
    non-zero (this is documented as a `MUST` requirement on
    `vpx_codec_ctrl_fn_map_t` in the internal header).
  2. Missing `iface`, `priv`, or `ctrl_maps` — the context is not
    initialized, or this codec exposes no controls at all. `ctrl_maps`
    being NULL is legitimate (a codec with no controls); the
    dispatcher treats that as `VPX_CODEC_ERROR` rather than
    `INCAPABLE` to distinguish "broken" from "this control isn't
    available".
  3. Linear search through the codec's mapping table. Each entry is
    `{ ctrl_id, fn }`; the loop terminates at the first `fn == NULL`.
    A match on `entry->ctrl_id == ctrl_id` invokes that function.
    The special case `entry->ctrl_id == 0` (with a non-NULL `fn`) is
    documented as a catch-all wildcard: a codec that wants to handle
    any control with one function can put `{ 0, my_fn }` at the front
    of its table.

The default-before-the-loop assignment `res = VPX_CODEC_INCAPABLE` is
what is returned if the loop falls off the end without matching — the
codec is alive but doesn't implement this particular request.

**The `va_list` lifetime invariant** is preserved exactly: `va_start`
runs only when a handler is about to be called, and `va_end` runs
before `break`. The variadic args are forwarded *as a va_list* to the
handler (whose prototype is
`vpx_codec_err_t (*)(vpx_codec_alg_priv_t *, va_list)`); the handler
extracts a single argument with `va_arg`. The matching `CAST(id, arg)`
helpers (defined in the internal header) generate per-ID inline
extractors so each callback knows the static type.

**Why the cast to `vpx_codec_alg_priv_t *`?** Same as in `destroy`:
the dispatcher only knows about the public `vpx_codec_priv` type, but
the contract is that each codec's larger private struct begins with
that struct and pointers are interchangeable.

## The internal error path

### `vpx_internal_error`

```c
void vpx_internal_error(struct vpx_internal_error_info *info,
                        vpx_codec_err_t error, const char *fmt, ...) {
  va_list ap;

  info->error_code = error;
  info->has_detail = 0;

  if (fmt) {
    size_t sz = sizeof(info->detail);

    info->has_detail = 1;
    va_start(ap, fmt);
    vsnprintf(info->detail, sz - 1, fmt, ap);
    va_end(ap);
    info->detail[sz - 1] = '\0';
  }

  if (info->setjmp) longjmp(info->jmp, info->error_code);
}
```

This is the file's exception-handling primitive. It is called from
deep inside the decoder — `vp8/decoder/decodeframe.c`,
`vp8/common/alloccommon.c`, `onyxd_if.c`, and many others — whenever
something goes wrong that should propagate all the way back to the
public API. The mechanism is `setjmp`/`longjmp` and the linkage
between the two ends is the `vpx_internal_error_info` struct, declared
at the bottom of `vpx_codec_internal.h`:

```c
struct vpx_internal_error_info {
  vpx_codec_err_t error_code;
  int has_detail;
  char detail[80];
  int setjmp;
  jmp_buf jmp;
};
```

A typical usage pattern: the public entry point — `vp8_decode` in
`vp8_dx_iface.c` — saves the `jmp_buf` with `if (setjmp(...))` and
sets `info->setjmp = 1`. It then calls into the decoder. Anywhere
inside that nested call tree, on encountering an unrecoverable
condition, code invokes `vpx_internal_error(info, code, fmt, ...)`
and control unwinds back to the `setjmp` site without manual
error-code propagation through every intermediate function.

The implementation:

  1. **Record the error code** on `info->error_code`. Even without a
    detail string, this preserves the diagnosis.
  2. **Reset `has_detail` to 0**, then format the optional
    `printf`-style message into the fixed 80-byte `detail` buffer
    using `vsnprintf`. The `sz - 1` cap and explicit NUL at
    `detail[sz - 1]` are belt-and-suspenders — `vsnprintf` is supposed
    to NUL-terminate within its supplied length, but the explicit
    write guarantees termination even on hostile libc implementations.
  3. **Long-jump if armed.** `info->setjmp` acts as a guard: code can
    legitimately call `vpx_internal_error` *before* a `setjmp` has
    been installed (during early construction, say), in which case it
    is a fatal-but-recorded condition and control returns normally.
    The caller is then responsible for propagating the error via
    ordinary return values.

The `LIBVPX_FORMAT_PRINTF(3, 4)` attribute on the prototype
(in the internal header) lets GCC verify the format string against
the variadic arguments at every call site.

`CLANG_ANALYZER_NORETURN` on the same prototype is the static
analyzer's hint that this function does not return in the common case
— important for clang's flow analysis, which otherwise would think
that the body of an `if (out_of_memory) vpx_internal_error(...)`
falls through.

**The interaction with `vpx_codec_error_detail`** is via the codec's
own private storage: after a `setjmp` returns non-zero, the codec
adapter copies `info->detail` into `priv->err_detail` (which is what
`vpx_codec_error_detail` reads). The `vpx_internal_error_info` struct
itself is owned by the algorithm — it typically lives inside the
larger common decoder state, e.g. `vp8/common/onyxc_int.h`'s
`VP8_COMMON::error`.

## What this file *doesn't* do

It is worth noting the boundaries of this file's responsibility, since
they are easy to get wrong from a casual read:

  - **No initialization.** `vpx_codec_dec_init_ver` lives in
    `vpx_decoder.c`. It is the function that takes the
    `VPX_DECODER_ABI_VERSION` argument, compares it against the
    library's compiled-in value (which is the sum of
    `VPX_CODEC_ABI_VERSION` and the decoder-specific bump), and
    returns `VPX_CODEC_ABI_MISMATCH` on disagreement. Once it agrees,
    it calls `iface->init`. This file only defines the
    `vpx_codec_err_to_string` mapping for that error code.
  - **No decode loop.** `vpx_codec_decode`, `vpx_codec_get_frame`,
    and `vpx_codec_peek_stream_info` are all in `vpx_decoder.c`.
    They use this file's `SAVE_STATUS` and `vpx_codec_iface_t`
    function-pointer slots, but they are not declared here.
  - **No encode entry points.** Those are in `vpx_encoder.c`, compiled
    unconditionally even in decoder-only builds (see the file list
    note in `documentation/vp8_files.md`: `vpx_encoder.c` is built
    even though its functions are no-ops without an encoder
    interface).
  - **No VP8-specific knowledge.** The string "VP8" does not appear
    anywhere in this file, by design. All codec-specific behavior is
    one indirection away through `ctx->iface->...`.

The result is a translation unit of roughly 130 lines that any new
codec can rely on unchanged. The cost of that decoupling is the
variadic `vpx_codec_control_` trampoline and the slightly indirect
error-detail storage; the benefit is that adding a third codec
(historically VP9, hypothetically anything else) requires zero
modifications here.
